# Data model

The tables, as the migrations in `backend/drizzle/` create them. Each table is
defined in its module's `infrastructure/*.table.ts`.

## `tools`

Defined in `backend/src/modules/tools/infrastructure/tools.table.ts`.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|

| `description` | `varchar(280)` | no | `''` | |
| `category` | `varchar(40)` | no | — | Free text. Grouped ignoring case in the UI |

## `atlas_spec_ids`

Saved Spec IDs. Defined in
`backend/src/modules/atlas/infrastructure/atlas-spec-ids.table.ts`. A row is
updated when its facts or name change, with `version` raised and an entry in
`atlas_spec_id_changes`; nothing deletes one
([ADR 0022](../decisions/0022-saved-spec-ids-can-be-edited-and-every-change-is-recorded.md)).
Migration 0011 converted every row saved before the S2 release, and every code
in `atlas_spec_id_changes`, to S2
([ADR 0024](../decisions/0024-spec-ids-move-to-the-s2-format.md)); migration
0012 then converted them all to the short form
([ADR 0025](../decisions/0025-spec-ids-are-written-short.md)).

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | — | Primary key. Generated by the application |
| `code` | `varchar(97)` | no | — | The whole Spec ID, short form (at most 94 characters). Unique |
| `product_type` | `varchar(3)` | no | — | Slot 1, raw text |
| `material` | `varchar(3)` | no | — | Slot 2 |
| `coating` | `varchar(2)` | no | — | Slot 3 |
| `colour_clarity` | `varchar(2)` | no | — | Slot 4 |
| `shape` | `varchar(2)` | no | — | Slot 5 |
| `profile` | `varchar(2)` | no | — | Slot 6 |
| `capacity` | `varchar(5)` | no | — | Slot 7 |
| `top_diameter` | `varchar(4)` | no | — | Slot 8 |
| `bottom_diameter` | `varchar(4)` | no | — | Slot 9 |
| `height` | `varchar(4)` | no | — | Slot 10 |
| `length` | `varchar(4)` | no | — | Slot 11 |
| `width` | `varchar(4)` | no | — | Slot 12 |
| `gusset` | `varchar(4)` | no | — | Slot 13 |
| `unit_weight` | `varchar(4)` | no | — | Slot 14 |
| `basis_weight` | `varchar(3)` | no | — | Slot 15 |
| `thickness` | `varchar(3)` | no | — | Slot 16 |
| `wall` | `varchar(2)` | yes | — | Slot 17. Null only on a row an S1 API saved during a deploy, which is read as its S1 code converts (ADR 0024); the same holds for the seven below |
| `print` | `varchar(2)` | yes | — | Slot 18 |
| `compartments` | `varchar(2)` | yes | — | Slot 19 |
| `plies` | `varchar(1)` | yes | — | Slot 20 |
| `lid_opening` | `varchar(2)` | yes | — | Slot 21 |
| `handle` | `varchar(2)` | yes | — | Slot 22 |
| `wrap` | `varchar(2)` | yes | — | Slot 23 |
| `window` | `varchar(2)` | yes | — | Slot 24 |
| `variant` | `varchar(2)` | no | — | Slot 25; always `X` for now |
| `name` | `varchar(120)` | no | — | 1–120 characters, trimmed |
| `dictionary_release` | `varchar(16)` | no | — | FK → `atlas_dictionary_releases.release` |
| `saved_by` | `uuid` | no | — | FK → `accounts.id` |
| `saved_at` | `timestamptz` | no | — | Set by the application's clock |
| `version` | `integer` | no | `1` | Raised by 1 on every saved change |
| `updated_by` | `uuid` | yes | — | FK `atlas_spec_ids_updated_by_fk` → `accounts.id`; null until the first change |
| `updated_at` | `timestamptz` | yes | — | Null until the first change |

Slot columns hold the slot's raw text, so `Y` (not known) and `X` (doesn't
apply) keep their meaning. A row an older API saved during a deploy may hold
its code and markers in the long form (`S2.`, `0000`, `XX`); it is read in the
short form, and lookups match it in either form.

**Indexes**

| Name | On | Why |
|---|---|---|
| `atlas_spec_ids_code_unique` | `code`, unique | One product, one code. Only the database can enforce that against two simultaneous saves; the repository turns a violation into `SPEC_ID_EXISTS` |
| `atlas_spec_ids_saved_at_idx` | `saved_at` | Lookups answer newest first |
| `atlas_spec_ids_<slot>_idx` | each slot column from `product_type` to `window` | The similar lookup filters on any of them |

| `code_after` | `varchar(97)` | no | — | |
| `name_before` | `varchar(120)` | yes | — | Null for `created` |
| `name_after` | `varchar(120)` | no | — | |
| `dictionary_change_number` | `integer` | yes | — | FK `atlas_spec_id_changes_dictionary_change_fk` → `atlas_dictionary_changes.number`: the approved dictionary change that made this change; null for anyone's own edit ([ADR 0031](../decisions/0031-the-dictionary-is-edited-by-suggestion-and-approval.md)) |

## `atlas_manufacturer_stage_changes`

Every change an admin made to a manufacturer's stage on a Spec ID (#57).
Defined in
`backend/src/modules/atlas/infrastructure/atlas-manufacturer-stage-changes.table.ts`.
Rows are only ever inserted. A manufacturer's current stage on a Spec ID is
the newest row's `stage_after`; with no row, or a null `stage_after`, its
quotes decide it ("Quoted" or "Specifications received"). The verified-list
import never touches this table, and never deletes a manufacturer, so a
re-import leaves every stage as it was
([ADR 0027](../decisions/0027-manufacturers-and-quotes-live-in-atlas-behind-sign-in.md)).

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | — | Primary key. Generated by the application |

| `manufacturer_id` | `uuid` | no | — | FK `atlas_manufacturer_stage_changes_manufacturer_id_fk` → `atlas_manufacturers.id` |
| `stage_before` | `varchar(16)` | yes | — | `sampling` or `in-production`; null when no admin had set one |
| `stage_after` | `varchar(16)` | yes | — | `sampling` or `in-production`; null is a cleared stage |
| `changed_by` | `uuid` | no | — | FK `atlas_manufacturer_stage_changes_changed_by_fk` → `accounts.id`. Always an admin: the route sits behind the admin gate |
| `changed_at` | `timestamptz` | no | — | The application's clock, or 1ms later when that clock is not after the change it replaces |

**Constraints and indexes**

| Name | On | Why |
|---|---|---|

| `atlas_stage_changes_spec_manufacturer_idx` | `spec_id, manufacturer_id, changed_at` | A manufacturer's newest change on a Spec ID |

## `atlas_dictionary_renames`

Every code an approved change renamed or deleted, and its live letters now.
Defined in `backend/src/modules/atlas/infrastructure/atlas-dictionary.table.ts`.
Flattened: renaming A to B, then B to C, leaves A → C and B → C, so one lookup
reaches the live letters. Code that names an S2 0.1.0 code reads it through
this table.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `slot` | `varchar(32)` | no | — | A dictionary slot key |
| `old_code` | `varchar(5)` | no | — | The letters it had |
| `new_code` | `varchar(5)` | yes | — | Its live letters; null once deleted |
| `change_number` | `integer` | no | — | FK `atlas_dictionary_renames_change_number_fk` → `atlas_dictionary_changes.number`: the change that last moved it |

**Constraints and indexes**

| Name | On | Why |
|---|---|---|
| `atlas_dictionary_renames_pk` | `slot, old_code`, primary key | One live code per old code |

## `atlas_dictionary_search_words`

Words an approved change gave an option, read in pasted text as that option
alongside the word list in the code
([ADR 0026](../decisions/0026-raw-text-is-read-by-rules-and-a-public-word-list.md)).
Defined in `backend/src/modules/atlas/infrastructure/atlas-dictionary.table.ts`.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `slot` | `varchar(32)` | no | — | A dictionary slot key |
| `word` | `varchar(40)` | no | — | Lower case, one space between words |
| `code` | `varchar(5)` | no | — | The option it finds; moved by a rename, deleted with its option |
| `change_number` | `integer` | no | — | FK `atlas_dictionary_search_words_change_number_fk` → `atlas_dictionary_changes.number`: the change that gave it |

**Constraints and indexes**

| Name | On | Why |

| `atlas_dictionary_search_words_pk` | `slot, word`, primary key | One meaning per word in each list |
