# Data model

The tables, as the migrations in `backend/drizzle/` create them. Each table is
defined in its module's `infrastructure/*.table.ts`.

## `tools`

Internal applications and links staff can open from the hub.
Defined in `backend/src/modules/tools/infrastructure/tools.table.ts`.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | — | Primary key. Generated by the application, not the database |
| `name` | `varchar(80)` | no | — | |
| `url` | `varchar(2048)` | no | — | `http:` or `https:` only — enforced by the domain, not the database |
| `description` | `varchar(280)` | no | `''` | |
| `category` | `varchar(40)` | no | — | Free text. Grouped ignoring case in the UI |
| `created_at` | `timestamp with time zone` | no | — | Set by the application's clock |

**Indexes**

| Name | On | Why |
|---|---|---|
| `tools_name_lower_unique` | `lower(name)`, unique | Names are unique ignoring case. Only the database can enforce that when two requests arrive at once; the repository turns a violation into `TOOL_NAME_TAKEN` |

## `accounts`

Staff who may use the Gateway once approved.
Defined in `backend/src/modules/accounts/infrastructure/accounts.table.ts`.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | — | Primary key. Generated by the application |
| `email` | `varchar(320)` | no | — | Stored lower-case. Unique |
| `full_name` | `varchar(81)` | no | — | Always `"First Last"` (trimmed), written with the two below. Kept for code that reads one name, such as Atlas's "saved by" |
| `first_name` | `varchar(40)` | no | `''` | Filled from `full_name` by migration 0008: everything before the first space |
| `last_name` | `varchar(40)` | no | `''` | The rest of `full_name` after its first space; empty for a one-word name. The application splits `full_name` the same way when it reads a row with both names empty |
| `password_hash` | `text` | no | — | `scrypt$…` — never a plain password |
| `must_change_password` | `boolean` | no | `false` | |
| `status` | `text` | no | — | Check: `pending`, `approved`, `disabled` |
| `failed_sign_in_count` | `integer` | no | `0` | |
| `locked_until` | `timestamptz` | yes | — | Set after five failed sign-ins |
| `created_at` | `timestamptz` | no | — | |
| `approved_by` | `uuid` | yes | — | FK → `accounts.id` |
| `approved_at` | `timestamptz` | yes | — | |

**Indexes**

| Name | On | Why |
|---|---|---|
| `accounts_email_unique` | `email`, unique | One account per company mailbox |
| `accounts_status_check` | check | Status is one of the three allowed values |

## `sessions`

| Column | Type | Null | Default | Notes |

| `account_id` | `uuid` | no | — | FK → `accounts.id` on delete cascade |
| `token_hash` | `text` | no | — | SHA-256 hex of the cookie token |
| `expires_at` | `timestamptz` | no | — | Renewed on each authenticated request (7-day window) |
| `last_seen_at` | `timestamptz` | no | — | |
| `created_at` | `timestamptz` | no | — | |

**Indexes**

| Name | On | Why |
|---|---|---|
| `sessions_token_hash_unique` | `token_hash`, unique | Look up a session from the cookie |

## `account_invites`

One-time public registration links an admin sends
([ADR 0023](../decisions/0023-accounts-are-created-by-invite-only.md)). The URL
holds the raw token; only `token_hash` is stored. Rows are never deleted.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | — | Primary key |
| `email` | `varchar(320)` | no | — | Lower-cased, as `accounts.email`. The account it creates gets this email |
| `token_hash` | `text` | no | — | SHA-256 hex |
| `invited_by` | `uuid` | no | — | FK → `accounts.id`. Becomes the new account's `approved_by` |
| `created_at` | `timestamptz` | no | — | |
| `expires_at` | `timestamptz` | no | — | 7 days from creation |
| `used_at` | `timestamptz` | yes | — | Set when an account is registered with it, in the same transaction |
| `revoked_at` | `timestamptz` | yes | — | Set when an admin revokes it, or when a newer invite to the same email replaces it |

**Indexes**

| Name | On | Why |
|---|---|---|
| `account_invites_token_hash_unique` | `token_hash`, unique | Look up an invite from the URL token |
| `account_invites_email_idx` | `email` | Find an email's open invite to replace it |

## `atlas_dictionary_releases`

Each released dictionary, `S1 0.1.0` and `S2 0.1.0` ([ADR 0021](../decisions/0021-the-atlas-dictionary-changes-only-by-migration.md),
[ADR 0024](../decisions/0024-spec-ids-move-to-the-s2-format.md)).
Defined in `backend/src/modules/atlas/infrastructure/atlas-dictionary.table.ts`,
like the two tables below. Filled only by migration; nothing in the
application writes these three tables.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `release` | `varchar(16)` | no | — | Primary key, e.g. `S1 0.1.0` |
| `approved_on` | `date` | no | — | |

## `atlas_dictionary_values`

The meaning of every dictionary code, per release. 28 rows for `S1 0.1.0`; 118
for `S2 0.1.0`.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `release` | `varchar(16)` | no | — | FK → `atlas_dictionary_releases.release` |
| `slot` | `varchar(32)` | no | — | Slot key: `productType`, `material`, `coating`, `colourClarity`, `shape`, `profile`, or `capacity` (its unit letters) |
| `code` | `varchar(5)` | no | — | Never `Y`, all `0` or all `X`: each reads as a marker ([ADR 0025](../decisions/0025-spec-ids-are-written-short.md)) |
| `meaning` | `varchar(120)` | no | — | |

**Indexes**

| Name | On | Why |
|---|---|---|
| `atlas_dictionary_values_release_slot_code_pk` | `release, slot, code`, primary key | One meaning per code, per slot, per release |
| `atlas_dictionary_values_code_not_marker` | check | A value must never read as a marker |

## `atlas_slot_rules`

Which slots apply to each product type, per release. 56 rows for `S1 0.1.0`:
fourteen ruled slots for each of four product types. 682 rows for `S2 0.1.0`:
twenty-two ruled slots for each of 31 product types.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `release` | `varchar(16)` | no | — | FK → `atlas_dictionary_releases.release` |
| `product_type` | `varchar(3)` | no | — | A `productType` code |
| `slot` | `varchar(32)` | no | — | Slot key, `coating` to `thickness` |
| `rule` | `varchar(16)` | no | — | `applies`, `never`, `round_only`, `non_round_only` or `paper_only` |

**Indexes**

| Name | On | Why |
|---|---|---|
| `atlas_slot_rules_release_product_type_slot_pk` | `release, product_type, slot`, primary key | One rule per slot, per product type, per release |
| `atlas_slot_rules_rule_check` | check | Only the five rules the encoder knows |

## `atlas_spec_ids`

Saved Spec IDs. Defined in
`backend/src/modules/atlas/infrastructure/atlas-spec-ids.table.ts`. A row is
updated when its facts or name change, with `version` raised and an entry in
`atlas_spec_id_changes`; nothing deletes one
([ADR 0022](../decisions/0022-saved-spec-ids-can-be-edited-and-every-change-is-recorded.md)).
Migration 0011 converted every row saved before the S2 release, and every code
in `atlas_spec_id_changes`, to S2
([ADR 0024](../decisions/0024-spec-ids-move-to-the-s2-format.md)); migration
0012 then converted them all to the short form
([ADR 0025](../decisions/0025-spec-ids-are-written-short.md)).

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | — | Primary key. Generated by the application |
| `code` | `varchar(97)` | no | — | The whole Spec ID, short form (at most 94 characters). Unique |
| `product_type` | `varchar(3)` | no | — | Slot 1, raw text |
| `material` | `varchar(3)` | no | — | Slot 2 |
| `coating` | `varchar(2)` | no | — | Slot 3 |
| `colour_clarity` | `varchar(2)` | no | — | Slot 4 |
| `shape` | `varchar(2)` | no | — | Slot 5 |
| `profile` | `varchar(2)` | no | — | Slot 6 |
| `capacity` | `varchar(5)` | no | — | Slot 7 |
| `top_diameter` | `varchar(4)` | no | — | Slot 8 |
| `bottom_diameter` | `varchar(4)` | no | — | Slot 9 |
| `height` | `varchar(4)` | no | — | Slot 10 |
| `length` | `varchar(4)` | no | — | Slot 11 |
| `width` | `varchar(4)` | no | — | Slot 12 |
| `gusset` | `varchar(4)` | no | — | Slot 13 |
| `unit_weight` | `varchar(4)` | no | — | Slot 14 |
| `basis_weight` | `varchar(3)` | no | — | Slot 15 |
| `thickness` | `varchar(3)` | no | — | Slot 16 |
| `wall` | `varchar(2)` | yes | — | Slot 17. Null only on a row an S1 API saved during a deploy, which is read as its S1 code converts (ADR 0024); the same holds for the seven below |
| `print` | `varchar(2)` | yes | — | Slot 18 |
| `compartments` | `varchar(2)` | yes | — | Slot 19 |
| `plies` | `varchar(1)` | yes | — | Slot 20 |
| `lid_opening` | `varchar(2)` | yes | — | Slot 21 |
| `handle` | `varchar(2)` | yes | — | Slot 22 |
| `wrap` | `varchar(2)` | yes | — | Slot 23 |
| `window` | `varchar(2)` | yes | — | Slot 24 |
| `variant` | `varchar(2)` | no | — | Slot 25; always `X` for now |
| `name` | `varchar(120)` | no | — | 1–120 characters, trimmed |
| `dictionary_release` | `varchar(16)` | no | — | FK → `atlas_dictionary_releases.release` |
| `saved_by` | `uuid` | no | — | FK → `accounts.id` |
| `saved_at` | `timestamptz` | no | — | Set by the application's clock |
| `version` | `integer` | no | `1` | Raised by 1 on every saved change |
| `updated_by` | `uuid` | yes | — | FK `atlas_spec_ids_updated_by_fk` → `accounts.id`; null until the first change |
| `updated_at` | `timestamptz` | yes | — | Null until the first change |

Slot columns hold the slot's raw text, so `Y` (not known) and `X` (doesn't
apply) keep their meaning. A row an older API saved during a deploy may hold
its code and markers in the long form (`S2.`, `0000`, `XX`); it is read in the
short form, and lookups match it in either form.

**Indexes**

| Name | On | Why |
|---|---|---|
| `atlas_spec_ids_code_unique` | `code`, unique | One product, one code. Only the database can enforce that against two simultaneous saves; the repository turns a violation into `SPEC_ID_EXISTS` |
| `atlas_spec_ids_saved_at_idx` | `saved_at` | Lookups answer newest first |
| `atlas_spec_ids_<slot>_idx` | each slot column from `product_type` to `window` | The similar lookup filters on any of them |

## `atlas_spec_id_changes`

Every change to a saved Spec ID, its creation first. Defined in
`backend/src/modules/atlas/infrastructure/atlas-spec-id-changes.table.ts`.
Rows are only ever inserted, in the same transaction as the change they
record ([ADR 0022](../decisions/0022-saved-spec-ids-can-be-edited-and-every-change-is-recorded.md)). Which slots changed is worked out by
comparing the two codes.

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | — | Primary key. Generated by the application (by the database for the backfill) |
| `spec_id` | `uuid` | no | — | FK `atlas_spec_id_changes_spec_id_fk` → `atlas_spec_ids.id` |
| `kind` | `varchar(16)` | no | — | `created` or `updated` |
| `changed_by` | `uuid` | no | — | FK `atlas_spec_id_changes_changed_by_fk` → `accounts.id` |
| `changed_at` | `timestamptz` | no | — | Set by the application's clock |
| `code_before` | `varchar(97)` | yes | — | Null for `created` |
| `code_after` | `varchar(97)` | no | — | |
| `name_before` | `varchar(120)` | yes | — | Null for `created` |
| `name_after` | `varchar(120)` | no | — | |

Migration `0006_backfill_atlas_spec_id_created_changes` gave every Spec ID
saved before this table existed its `created` entry, from `saved_by` and
`saved_at`.

**Constraints and indexes**

| Name | On | Why |
|---|---|---|
| `atlas_spec_id_changes_kind_check` | check | Only the two kinds |
| `atlas_spec_id_changes_spec_id_changed_at_idx` | `spec_id, changed_at` | A Spec ID's history, newest first |
| `atlas_spec_id_changes_code_before_idx` | `code_before` | A pasted old code finds the Spec IDs it once belonged to |
